# jg 무인자 실행 시 main working tree 최상단 고정

## 한 줄 정의

git 저장소 안에서 `jg`를 인자 없이 실행하면, 현재 저장소의 main working tree 경로를 fzf 피커 최상단에 라벨과 함께 고정해 한눈에 고를 수 있게 한다.

## 배경이 되는 사용 맥락

`jg`는 frecency 기반으로 추적 중인 git 저장소들을 fzf 피커로 보여주고, 선택한 경로로 셸이 `cd` 하게 하는 도구다. git worktree를 쓰면 하나의 저장소가 main working tree와 여러 linked worktree로 나뉘는데, linked worktree 안에서 작업하다 main working tree로 돌아가고 싶을 때가 잦다. main working tree 하위 디렉토리 깊숙이 들어가 있다가 저장소 루트로 돌아가고 싶은 상황도 마찬가지다.

지금은 `jg`를 인자 없이 실행하면 추적 중인 모든 저장소에 대한 fzf 피커가 뜨고, 그 안에서 사용자가 직접 main 경로를 찾아 입력·선택해야 한다. 현재 저장소의 main이 frecency 상위에 있으리라는 보장이 없어, 돌아가려는 대상이 목록 아래쪽에 묻히기도 한다.

이 기능은 "현재 git 저장소의 main working tree"라는, 그 순간 가장 돌아갈 법한 목적지를 피커 맨 위에 고정 노출해 그 마찰을 없앤다.

## 대상 사용자

`jg`로 저장소 사이를 이동하면서 git worktree를 함께 쓰는 사용자. 특히 linked worktree에서 작업하다 main working tree로 자주 오가거나, 저장소 하위 디렉토리에서 루트로 빠르게 돌아가려는 사용자.

## 목표

- git 저장소 안에서 `jg`를 인자 없이 실행하면, 그 저장소의 main working tree 경로가 피커 최상단에 고정되고 다른 항목과 구분되는 라벨로 표시된다.
- 고정된 main 항목을 선택하면 셸이 그 경로로 `cd` 한다.
- 기존의 frecency 기반 피커 동작은 그대로 보존한다. main 고정은 피커 위에 한 줄 얹는 것일 뿐, 나머지 목록의 정렬·표시·preview는 바뀌지 않는다.

## 비목표

- main으로의 자동 직행(피커 없이 곧장 `cd`)은 하지 않는다. 피커는 항상 뜨고 선택은 사용자가 한다.
- 인자나 쿼리가 있는 실행(`jg <query>`)의 동작은 바꾸지 않는다. main 고정은 무인자 실행에서만 일어난다.
- `jgw`(worktree 전용 점프 명령)의 동작은 바꾸지 않는다. 이 기능은 `jg` 본체에만 추가한다.
- 새로운 frecency 가산이나 점수 보정을 도입하지 않는다. main은 점수와 무관하게 고정된다.

## 기능 범위

### 트리거 조건

`jg`를 인자 없이 실행한 경우(`runJump`에 쿼리 인자가 비어 있을 때)에만 main 고정을 시도한다. 다음 조건을 모두 만족할 때 main을 고정한다.

- 현재 작업 디렉토리(cwd)가 git 저장소 안이다.
- 그 저장소의 main working tree 루트 경로를 구할 수 있다.
- cwd가 main working tree 루트와 **정확히 일치하지는 않는다**. 이미 main 루트에 서 있으면 돌아갈 대상이 자기 자신이라 고정할 의미가 없으므로 생략한다. (main working tree 하위 디렉토리에 있을 때는 cwd != main 루트이므로 정상적으로 고정된다.)

위 조건을 하나라도 만족하지 못하면(저장소 밖이거나, main 경로를 못 구하거나, cwd가 곧 main 루트이거나) main 고정 없이 기존 피커를 그대로 띄운다.

### main working tree 경로 결정

cwd가 속한 저장소의 worktree 목록을 git에서 읽어, main으로 표시된 working tree의 루트 경로를 main 경로로 삼는다. linked worktree 안에 있으면 그 부모 격인 main working tree 루트가, main working tree 하위 디렉토리에 있으면 그 저장소 루트가 main 경로가 된다.

저장소의 worktree 목록 조회와 main 식별은 기존 `internal/worktree` 패키지의 `List` 및 main 판별 로직을 재사용한다.

### 피커에서의 표현

- main 경로는 피커 최상단에 고정한다. frecency 점수와 무관하게 항상 맨 위 한 줄을 차지한다.
- main 줄은 다른 항목과 구분되는 라벨을 단다. 예: `↑ main  ~/repo` 형태로, 화살표·`main` 표식과 함께 축약된 경로를 보여준다.
- main 경로가 frecency 추적 목록에도 들어 있으면, 본문 목록에서는 그 항목을 제거해 중복 표시를 막는다. main은 고정 줄로만 한 번 나타난다.
- 나머지 항목은 기존과 동일하게 frecency 순서로, 기존 표시(`~` 축약)와 preview를 유지한다.

### 선택 결과 처리

피커가 반환하는 값에서 실제 저장소 경로를 추출해, 기존과 동일하게 표준 출력으로 그 경로를 찍는다. 셸 래퍼가 그 경로로 `cd` 한다. main 줄을 골랐든 일반 항목을 골랐든, 최종적으로 셸에 넘어가는 것은 순수 경로 문자열이어야 한다.

## 주요 시나리오

1. **linked worktree에서 main으로 돌아가기**: 사용자가 `~/repo/.worktrees/feature-x` 같은 linked worktree 안에서 `jg`를 인자 없이 실행한다. 피커 최상단에 `↑ main  ~/repo`가 고정되어 뜨고, 사용자가 그것을 선택하면 셸이 `~/repo`로 `cd` 한다.

2. **main 저장소 하위 디렉토리에서 루트로**: 사용자가 `~/repo/src/internal/foo`에서 `jg`를 인자 없이 실행한다. 최상단에 `↑ main  ~/repo`가 고정되어, 선택 시 저장소 루트로 돌아간다.

3. **저장소 밖에서 평소처럼**: 사용자가 git 저장소가 아닌 디렉토리에서 `jg`를 인자 없이 실행한다. main 고정 없이 기존 frecency 피커가 그대로 뜬다.

4. **이미 main 루트에 서 있을 때**: 사용자가 `~/repo`(main working tree 루트) 바로 그 자리에서 `jg`를 인자 없이 실행한다. 돌아갈 main이 자기 자신이라 고정을 생략하고, 기존 frecency 피커를 그대로 띄운다.

5. **쿼리와 함께 실행**: 사용자가 `jg foo`처럼 쿼리를 준다. main 고정은 일어나지 않고 기존 쿼리 동작 그대로 작동한다.

## 수용 기준

- linked worktree 안에서 무인자 `jg` 실행 시, 피커 입력의 첫 항목이 그 저장소의 main working tree 경로이고 라벨이 붙는다.
- main working tree 하위 디렉토리에서 무인자 `jg` 실행 시, 첫 항목이 저장소 루트 경로다.
- cwd가 main 루트와 정확히 일치하면 고정 항목이 추가되지 않는다.
- 저장소 밖에서 무인자 `jg` 실행 시 고정 항목이 추가되지 않는다.
- main 경로가 frecency 목록에도 있을 때, 피커에 그 경로가 두 번 나타나지 않는다.
- 고정된 main 줄을 선택하면 표준 출력으로 라벨이 아닌 순수 경로가 나온다.
- 쿼리 인자가 있는 실행에서는 고정 항목이 추가되지 않는다.

## 설계 결정과 근거

### main 고정은 자동 직행이 아니라 피커 위 고정으로 한다

worktree에서 무인자 `jg`가 곧장 main으로 `cd` 하게 만들면, 그 맥락에서 frecency 피커로 다른 저장소를 고르는 기존 능력을 잃는다. 피커를 유지하고 main만 최상단에 얹으면, 한 번의 엔터로 main에 가면서도 다른 목적지를 고를 자유가 남는다. 기존 동작을 깨지 않는 비파괴적 확장이라는 점이 이 선택을 유지하는 영구적 근거다.

### main은 frecency 점수 보정이 아니라 점수와 무관한 고정으로 노출한다

점수를 인위적으로 올려 상위에 띄우는 방식은 보정 폭에 따라 다른 저장소를 밀어내거나 충분히 못 올라오는 경계 사례가 생긴다. 점수 체계 밖에서 별도 고정 줄로 다루면 "현재 저장소의 main은 항상 맨 위"라는 규칙이 점수 분포와 무관하게 항상 성립한다. 동작이 예측 가능하다는 점이 이 선택의 근거다.

### 피커 입력은 표시 라벨과 경로를 분리한 형식으로 넘긴다

fzf는 입력으로 받은 줄을 그대로 표시하고 그대로 반환한다. main 줄에 라벨을 섞어 넣으면 선택 결과에서 경로를 도로 파싱해야 하고, 그 파싱이 라벨 문자열 형태에 의존하면 취약하다. 입력을 "표시할 라벨"과 "반환할 경로" 두 영역으로 나눈 형식(예: 탭으로 구분한 두 열)으로 넘기고, fzf가 표시 영역만 보여주고 반환 줄에서 경로 영역만 떼어내게 하면, 라벨과 반환값이 깔끔히 분리된다. 이 분리는 구형 fzf에서도 동작하며, 기존 `~` 축약·preview 로직과 충돌하지 않는다.

### cwd가 main 루트와 정확히 일치하면 고정을 생략한다

이미 main 루트에 서 있으면 고정 항목이 가리키는 곳이 자기 자신이라, 선택해도 제자리이고 피커 맨 위 한 줄만 낭비한다. 이 경우에만 고정을 생략하면, main 저장소 하위 디렉토리(루트로 돌아가는 것이 유용한 경우)에서는 정상 동작하면서 의미 없는 자기 참조 줄만 걸러진다.

## 외부 의존

- `git` 명령(worktree 목록 조회, 저장소 루트 판별). 기존 `jg`가 이미 의존한다.
- `fzf`(대화형 피커). 기존 `jg`가 이미 의존한다.
- 표준 출력 경로를 받아 `cd` 하는 셸 래퍼(`plugin/jg.plugin.zsh`, `jg.plugin.bash`). 기존 구조 그대로 사용한다.
